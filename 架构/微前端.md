# 从0到1构建一个微前端应用

## 微前端介绍

定义：微前端是一种多个团队通过独立发布功能的方式来共同构建现代化 web 应用的技术手段及方法策略。

微前端具备以下几个核心价值：

- 技术栈无关：主框架不限制接入应用的技术栈，微应用具备完全自主权
- 独立开发、独立部署：微应用仓库独立，前后端可独立开发，部署完成后主框架自动完成同步更新。
- 增量升级：在面对各种复杂场景时，我们通常很难对一个已经存在的系统做全量的技术升级和重构，而微前端是一种非常好的事实渐进式重构的手段和策略。
- 独立运行时：每个微应用之间状态隔离，运行时状态不共享。

#### 父应用

概述：
父应用（也称主应用）是微前端架构中的核心应用，负责：

- 注册和管理微应用
- 提供共享容器和布局
- 协调路由和导航
- 传递数据给子应用
- 处理全局状态

1、 配置微应用注册信息
**文件**: [src/micro/apps.ts](../src/micro/apps.ts)
这是配置微应用的关键文件，定义了所有子应用的信息：

```typescript
const apps = [
  {
    /**
     * name: 微应用名称
     * - 必须与子应用 package.json 的 name 字段一致
     * - 必须与子应用 vite.config.js 中 qiankun 插件的第一参数一致
     * - 必须唯一，不能重复
     */
    name: 'qian_kun_vue',

    /**
     * entry: 子应用入口地址
     * - 开发环境: //localhost:5174 (子应用端口)
     * - 生产环境: https://yourdomain.com/subapp
     * - 使用 // 开头可以自动适配 http/https 协议
     */
    entry: '//localhost:5174',

    /**
     * container: 微应用挂载节点
     * - 必须是父应用中存在的 DOM 元素选择器
     * - qiankun 会将子应用渲染到这个容器中
     * - 建议使用 id 选择器 (#frame)
     */
    container: '#frame',

    /**
     * activeRule: 微应用激活规则
     * - 当浏览器 URL 匹配此规则时，加载对应的微应用
     * - 可以是字符串、数组、或函数
     * - 与子应用路由的 base(子应用路由配置) 必须保持一致
     */
    activeRule: '/vue',

    /**
     * props: 传递给子应用的数据
     * - 可以是任何类型的数据
     * - 子应用通过生命周期函数的 props 参数接收
     */
    props: {
      token: 'main-app-token',
      userInfo: { name: '张三' },
      // 可以传递函数
      onGlobalStateChange: (state, prev) => {},
      setGlobalState: (state) => {}
    }
  }
]
export default apps
```

重要配置说明：
activeRule 的几种写法：

```typescript
// 1. 字符串匹配（前缀匹配）
activeRule: '/vue'  // 匹配 /vue、/vue/home、/vue/about 等

// 2. 数组匹配
activeRule: ['/vue', '/micro']  // 匹配多个路径

// 3. 函数匹配（更灵活）
activeRule: (location) => {
  // 只有当 path 以 /vue 开头时才激活
  return location.pathname.startsWith('/vue')
}

// 4. 正则匹配
activeRule: /^\/vue/
```

entry 的配置方式

```typescript
// 1. 开发环境 - 使用子应用端口
entry: '//localhost:5174'

// 2. 生产环境 - 使用实际域名
entry: '//www.example.com/subapp'

// 3. 使用 HTML 入口（完整路径）
entry: '//localhost:5174/index.html'

// 4. JS 配置入口（高级用法）
entry: {
  scripts: ['//localhost:5174/src/main.js'],
  styles: ['//localhost:5174/style.css']
}
```

2、 配置 qiankun 启动
**文件**: [src/micro/index.ts](../src/micro/index.ts)
这个文件负责注册微应用并启动 qiankun。

```typescript
// micro-app-main/src/micro/index.ts
import NProgress from "nprogress"
import "nprogress/nprogress.css"
import { message } from "ant-design-vue"
import {
  registerMicroApps,
  addGlobalUncaughtErrorHandler,
  start,
} from "qiankun"

// 微应用注册信息
import apps from "./apps"

/**
 * 注册微应用
 * @param {Array} apps - 微应用注册信息数组
 * @param {Object} lifeCycles - 全局生命周期钩子
 */
registerMicroApps(apps, {
  // 📌 beforeLoad: 微应用加载之前
  beforeLoad: (app) => {
    console.log('[qiankun] before load', app.name)
    NProgress.start()  // 显示加载进度条
    return Promise.resolve()
  },

  // 📌 beforeMount: 微应用挂载之前
  beforeMount: (app) => {
    console.log('[qiankun] before mount', app.name)
    return Promise.resolve()
  },

  // 📌 afterMount: 微应用挂载完成
  afterMount: (app) => {
    console.log('[qiankun] after mount', app.name)
    NProgress.done()  // 隐藏加载进度条
    return Promise.resolve()
  },

  // 📌 beforeUnmount: 微应用卸载之前
  beforeUnmount: (app) => {
    console.log('[qiankun] before unmount', app.name)
    return Promise.resolve()
  },

  // 📌 afterUnmount: 微应用卸载完成
  afterUnmount: (app) => {
    console.log('[qiankun] after unmount', app.name)
    return Promise.resolve()
  }
})

/**
 * 添加全局的未捕获异常处理器
 * 用于处理微应用加载失败等错误
 */
addGlobalUncaughtErrorHandler((event: Event | string) => {
  console.error('[qiankun] error', event)
  const { message: msg } = event as any

  // 加载失败时提示
  if (msg && msg.includes("died in status LOADING_SOURCE_CODE")) {
    message.error("微应用加载失败，请检查应用是否可运行")
  }
})

/**
 * 导出 qiankun 的启动函数
 * @param {Object} options - qiankun 启动配置
 */
export default function startQiankun(options?: any) {
  start({
    // 📌 sandbox: 样式隔离和沙箱配置
    sandbox: {
      // 严格样式隔离（实验性功能）
      // 会对微应用的样式添加特定的选择器，避免样式冲突
      experimentalStyleIsolation: true,

      // 是否开启沙箱
      // strictStyleIsolation: true  // 更严格的样式隔离
    },

    // 📌 prefetch: 预加载策略
    prefetch: true,  // 在主应用加载完成后，预加载所有微应用的静态资源

    // 其他可选配置:
    // fetch: window.fetch,  // 自定义 fetch 方法
    // singular: false,      // 是否为单实例场景
    // getTemplate: (tpl) => tpl,  // 自定义 HTML 模板处理函数
  })
}
```

3、配置应用入口
**文件**: [src/main.js](../src/main.js)

在主应用入口中启动 qiankun。

```javascript
import { createApp } from "vue"
import App from "./App.vue"
import router from "./routes"
import ElementPlus from "element-plus"
import "element-plus/dist/index.css"
import * as ElementPlusIconsVue from "@element-plus/icons-vue"
import startQiankun from "./micro"  // 导入 qiankun 启动函数 ⭐

const app = createApp(App)

// ==================== qiankun 配置 ====================
// 开始微应用
// ⚠️ 注意：必须在 app.mount() 之前启动 qiankun
startQiankun({
  sandbox: {
    experimentalStyleIsolation: true,  // 开启样式隔离
  },
  prefetch: true,  // 开启预加载
})
// =====================================================

// Register all icons
for (const [key, component] of Object.entries(ElementPlusIconsVue)) {
  app.component(key, component)
}

app.use(ElementPlus)
app.use(router)
app.mount("#app")
```

**执行顺序很重要**:

```javascript
// ✅ 正确顺序
startQiankun()  // 1. 先启动 qiankun
app.use(router)
app.mount("#app") // 2. 再挂载主应用

// ❌ 错误顺序
app.mount("#app")  // 先挂载主应用
startQiankun()     // 后启动 qiankun - 可能导致问题
```
